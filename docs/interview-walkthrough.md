# Technical interview walkthrough

## Why a modular monolith?

The important boundaries are authorization, document access and durable workflow state. Keeping domain modules in one FastAPI application reduces distributed transactions and duplicated policy code. Celery separates expensive work without introducing independent services that each need a new security model. Scale and organizational ownership can justify splitting modules later.

## Why both application checks and PostgreSQL RLS?

Every API and agent tool authorizes the caller, including metadata and storage access. Restricted PostgreSQL roles and document RLS add a second barrier against accidentally broad queries. Transaction-local context prevents pooled-connection identity leakage. RLS is deliberately described as coverage for selected tables rather than as a universal tenant-isolation guarantee. SQLite testing cannot establish the PostgreSQL property.

## Why OIDC and a backend session?

OIDC delegates password storage and identity lifecycle to an established identity provider. Code flow with PKCE and HTTP-only session cookies reduce token exposure to browser JavaScript. Authorization still comes from current local database memberships; trusting a role supplied by an agent or blindly provisioning token claims would allow privilege escalation. Provider-wide revocation and local session invalidation are related but distinct operations.

## Why constrained agents and deterministic workflows?

Models help interpret documents and draft structured output. Schema validation, allowed tools, budgets and timeouts bound that assistance. Approval transitions, arithmetic, conflict detection and consequential state changes belong to deterministic code. Durable run/step records support recovery; idempotency and atomic decisions prevent duplicate execution. There is no generic SQL/shell/HTTP tool for a model to repurpose.

## Why hybrid retrieval and citations?

Lexical search works without paid embeddings and handles exact invoice/contract identifiers. Semantic retrieval improves paraphrase matching when real embeddings are available. Both paths must filter permissions before model context is built. Citation references are evidence links to accessible chunks, not merely plausible text generated by a model. Reranking has latency/model-dependency tradeoffs and should be enabled only after measured value.

## What does a test-only model prove?

It proves orchestration, schemas, API behavior and deterministic failure handling. It cannot prove real-provider extraction accuracy, safety, latency or cost. Those require repeated measured campaigns with real providers. The UI reports missing providers explicitly. Deterministic provider doubles are restricted to tests, so a configured real provider is required for interactive AI.

## What would change before a real enterprise rollout?

Validate corporate SSO, data retention and provider contracts; operate malware scanning and identity lifecycle; run an external security review; establish restore drills, on-call routing and service objectives; validate queue recovery and PostgreSQL isolation under production credentials. Replace public demo fixtures, pin release digests, budget model spend and rehearse rollback with backward-compatible migrations. The repository supplies implementation and infrastructure definitions, not evidence that these operational responsibilities have already been completed.
